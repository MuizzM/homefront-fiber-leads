# UI audit, August 2026

This is a mature product with a real design system and a half-finished migration through it. `docs/DESIGN_SYSTEM.md` is a genuine source of truth, `client/src/components/ui/page-scaffold.tsx` is a genuine shared grammar, `ErrorState`, `EmptyState`, `KpiTile`, `Button`, `Input` and the `min-h-tap` / `.tap-expand` / `.reveal-on-hover` utilities all exist and are all correct, and four unit tests already pin the rules that matter most (type floors, tap floors, page-title treatment, error-states-are-not-empties). The problem is adoption, not design. Eleven cluster audits over sixty-six screens produced 608 confirmed findings, and the overwhelming majority are the same eight or nine defects repeated: a query with no error branch that renders its empty copy on failure, a raw dark-ground palette step left over from when dark was the default, a hand-rolled control that missed the 44px floor because it never went through the primitive, an ARIA role announced without the keyboard model behind it, and a stat strip, page header or empty state re-derived by hand for the twentieth time. Two of those defects are worse than they look, because they are invisible at review time: `bg-success/8` and `bg-primary/12` generate no CSS at all in this project's Tailwind build, and roughly a third of the contrast failures only appear in one theme. Nine of thirty-seven pages use the shared `PageHeader`; that ratio holds for the rest of the grammar too, and it is the single number that best describes the state of the front end.

Counts by severity: **25 blocker, 129 high, 229 medium, 225 low**. A handful of entries are the same defect filed from two clusters (`EmptyState`'s dead `icon` prop, `sheet.tsx`'s doubled Close, the dead opacity steps); they are counted once per filing below and deduped in the cross-cutting program.

## Load time

Measured baseline, verbatim: entry index chunk 191 KB raw / 61 KB gzip, vendor-react 143 KB / 46 KB gzip, app stylesheet 149 KB raw / 35.5 KB gzip and render-blocking, trainingContent 452 KB / 148 KB gzip shipped as JavaScript, mapLibraryChunk 1.05 MB / 284 KB gzip, Training route 191 KB / 57 KB gzip.

Route-level code splitting, idle prefetch, keep-alive stages and stale-chunk recovery reload are already in place. What is not:

**Ship `trainingContent` as data, not as JavaScript.** 452 KB raw / 148 KB gzip is the single largest non-map asset and it is a corpus, not code. As a JS chunk it is parsed and compiled by the engine and versioned with every build; as a fetched JSON asset it is `Cache-Control`-able independently of deploys and costs a network read plus `JSON.parse`. Saves 148 KB gzip of JS parse and compile from the Training and Coach routes, and roughly halves the 191 KB / 57 KB Training route chunk. This is not a pure win to be taken blindly: the corpus is already lazily loaded via `useTrainingCorpus`, and its in-flight window is exactly what causes four confirmed false-empty states (`WhatNextSheet:124` and `:133`, `Coach:234`, `FlashcardDeck:51`). Do the honest loading states in the same change, or the saving buys a worse screen.

**Split the render-blocking stylesheet.** 149 KB raw / 35.5 KB gzip blocks first paint on every route, including the map, where the visible above-the-fold surface is a canvas and a handful of glass capsules. Extract the shell plus first-view rules into an inline critical block and defer the rest. The exact saving needs a Chrome coverage run rather than a guess, but the shape of the win is the whole non-critical remainder off the critical path. Two cheap reductions are available first: 126 dead `/8` and `/12` opacity call sites generate no rules but do bloat the class strings and the safelist surface, and `index.css` carries a ten-token `sidebar` palette from the shadcn scaffold that no call site references.

**Confirm `mapLibraryChunk` never enters a non-map route's graph.** At 1.05 MB / 284 KB gzip it dwarfs everything else; the cluster evidence says it is already dynamically imported (`LiveMap` polls for `mgl` before constructing a map, `LiveOps` and `MapView` both branch on load failure). The work is verification plus intent-based prefetch: `Layout.tsx` already ships `navIntentHandlers` on every nav link, so the map chunk can start downloading on pointer-down over the Map tab rather than on route commit. That converts a 284 KB gzip stall into overlap with the tap. Separately, audit whether the build pulls in MapLibre plugins the app does not use; the app draws raster XYZ tiles, GeoJSON sources, circle, line, fill and symbol layers, and nothing else.

**Delete the code that cannot run.** Three `PropertyDetail` summary variants where one ships, three `LeadCard` layouts where one is correct, 143 unreachable lines of `KnockLogger` in `Leads.tsx` plus its Dialog wrapper, and roughly thirty Lucide icons imported into `TABS` arrays and dead `icon` props across `FiberIntelligence`, `KineticScanner`, `Scanners`, `Messages`, `Leaderboard`, `ModeStrip`, `NumbersGame` and `PsychologyDeck`. Individually small, collectively tens of KB raw off the two largest page chunks, and each deletion removes a divergence that no test covers.

**Stop mounting two subtrees per row.** `CommissionConsole:421` and `:453`, and `Team:641` and `:652`, both render a mobile list and a desktop table simultaneously and hide one with CSS, so every viewport reconciles both. This costs no bytes and no paint (`display:none` skips layout) but it doubles the fiber and DOM node count on two of the heaviest tables in the app. `client/src/hooks/use-mobile.tsx` is already `matchMedia`-based and jsdom-safe. Related and worse: `Team.tsx:536` declares `RoleSection` inside the component, so React sees a new component type on every render and unmounts and remounts all three roster sections on every keystroke, toast and mutation. That one is a real frame-time defect, not a node-count one.

`vendor-react` at 143 KB / 46 KB gzip is the floor and there is nothing to do about it. The 191 KB / 61 KB entry chunk is worth one audit pass to confirm no page-level module is leaking into it through a `shared/` import.

## What this audit did not cover

- **Contrast was computed, not measured.** `docs/DESIGN_SYSTEM.md` is explicit that the check that matters walks the live DOM and resolves each text node's real composited background. Almost every figure here was computed from token values and class strings. The four documented gotchas (keep-alive stages returning hidden headings, stale layouts after a resize, gradients reporting transparent, empty screens hiding their colours) all apply, and the last one especially: several screens were read with no data in them.
- **Dark theme was not swept.** A handful of findings are dark-only (`text-white` on `bg-destructive` at 2.99:1, `bg-warning` at 2.0:1, `AlertDialogAction` not forwarding a variant) and were caught only because a reviewer thought to check. There has been no systematic dark pass.
- **No real assistive-technology run.** Every accessibility finding is from source: a missing `role`, an unimplemented keyboard contract, an `aria-label` on a role-less div. Nobody drove these screens with VoiceOver or a keyboard.
- **Nothing server-side.** Where a fix requires an endpoint change (the follow-up callback path, a `territoryId` filter on the leads list, an invite endpoint, `actorName` on area events) the client-side shape is described and the server work is not scoped.
- **No offline or queue behaviour.** `knockQueue` and the offline banners appear only where a component touches them.
- **No performance profiling.** The load-time section reads build output only. There are no traces, no coverage runs, no field measurements.
- **Print, internationalisation and reduced-motion were not examined**, beyond `CommissionStatement`'s deliberate hex palette and the `prefers-reduced-transparency` fallback that already exists for the glass bar.
- **The enhancements are unbuilt.** Each names a file and a change, none has been prototyped, and none has been validated with a rep or a manager.
- **Five of the eleven clusters returned no enhancement research at all** (people and governance, provider orders, training, scanners, app shell). Those surfaces have defect coverage and no design proposals.
- **Routes not in the ledger were not looked at.** If a route exists that no cluster listed, it is unaudited, not clean. The ledger's one genuinely clean entry is `ObjectionChips`.
- **The dashboards cluster never ran.** It was commissioned as one of twelve and died mid-response on an API error, so eleven cluster audits are reported here, not twelve. `pages/Dashboard.tsx`, `pages/Metrics.tsx` and everything under `components/metrics/` are therefore absent from the ledger entirely - not clean, unexamined. Dashboard is the landing screen for every office role, and the prior `docs/ux-inventory.md` recorded three different stat presentations on it plus a `clockSessions.filter` recomputed four times per render on a 15-second poll; none of that was re-verified here. Re-running that one cluster is the cheapest gap to close.
- **The Mobbin connector was down for most of the run.** Six clusters (rep daily loop, map, leads and territory, calling, and both money surfaces) completed their reference research before it began timing out; the other five were re-run with the connector explicitly removed from their brief so they would stop retrying a dead server. That is why their enhancement lists are empty, and it is a connectivity artefact, not a judgement that those surfaces need no design work.

## Sequencing

Foundations before adoption, adoption before polish. The order matters because most of the 608 findings are instances of a dozen defects, and fixing the primitive is cheaper than fixing every instance.

**1. Compile-level and token-level fixes (days, one-line edits, unblock everything else).** Kill the 126 dead `/8` and `/12` classes and add the lint test that stops them coming back. Add `--primary`, `--success`, `--warning`, `--destructive` and `--info` to `.glass-ink-scope` (one edit fixes `AddLeadSheet`'s invisible primary control and every future glass surface). Add `--warning-foreground` and `--success-foreground`, which do not exist, so nobody guesses `text-white` again. Fix the five contrast blockers where a commit control's own label is unreadable: `CallingLead:576` and `:625`, `MapLensNotice:40`, `CityScanner:676` and `:617`. These are done first because they are single-token edits with the highest user impact per line changed, and because leaving them means every screen migrated in step 4 inherits them.

**2. The honesty program (weeks).** Establish the three-way query convention, then work it through the 121 state-coverage findings in traffic order: Today, MapView, Leads, MyCommission, CallingQueue, Team, ActionApprovals, OrderMessaging, LoginActivity, Governance. Extend `tests/rtl/ErrorStatesAreNotEmpties.test.tsx` from three screens to a lint over every `useQuery` call site, because this defect has already been fixed by hand on individual screens (`Today`, `LiveOps`, `Mileage`'s trip log all carry comments saying so) and has kept recurring in their siblings. This is second, not first, because it is the largest body of work and it must not block the one-line fixes.

**3. Fill the gaps in the primitives (small, and it gates step 4).** Make `EmptyState.icon` optional and delete its dead `TONES` entries; add a `loading` prop to `StatTile`; add an `as` prop to `SectionLabel`; let `StatStrip` take 5 columns; add an eyebrow slot to `EmptyState`; teach `AlertDialogAction` to forward a variant; build `client/src/components/ui/tabs.tsx`. Every one of these is currently a reason a screen cannot migrate without regressing, so they come before adoption, not during it.

**4. Adoption, screen by screen, in traffic order.** `MyCommission` and `CommissionConsole` first, because they import nothing from `components/ui` at all and are the two highest-value money screens. Then `Today`, the screen that teaches a rep what this app looks like and currently contradicts `PageHeader`, `StatStrip`, `EmptyState` and `ErrorState` at once. Then `Team`, `Applications`, `Leads`, `Diagnostics`, `Governance`, `LoginActivity`. Delete the local twins as you go: the shadowing `EmptyState` in `MyCommission`, the shadowing `SectionLabel` in `PropertyDetail`, the four hand-rolled stat strips, the six status-chip maps. Take the dead `icon` props and orphaned whitespace out in the same commits, because they are in the same lines.

**5. Touch and accessibility (parallel with 4, different reviewer).** The 56 sub-44px controls, the ten modals missing a keyboard contract, the nine unimplemented tab and radiogroup contracts, the twelve colour-only carriers, the eleven hover-only affordances, and the label-to-input associations in `SuperAdmin`, `KineticScanner`, `RecoveryCase`, `OrderImports` and `OrderMessaging`. Widen the floors test's `interactive` regex to a backward window first, so newly hand-rolled controls stop escaping it. This can run alongside adoption because it touches different lines on the same files, but it should be a separate review pass with a keyboard and a screen reader, since none of these findings has been verified that way.

**6. Delete the unfinished experiments, then the load-time work.** The three-variant `LeadCard` and `PropertyDetail`, the unreachable `KnockLogger`, the dead imports. Then `trainingContent` as data (paired with its loading states, which step 2 will already have built), the critical-CSS split, the map-chunk prefetch, and the doubled subtrees in `Team` and `CommissionConsole`. Deletion first because it shrinks what the load-time work has to reason about.

**7. The Mobbin enhancements, last, and only the ones whose defect is already fixed.** Several are entangled with earlier steps and get cheaper once those land: the Grab select-then-commit pattern needs the callback path from step 2, the Mistral counted-chips entry needs the query states from step 2, the DoorDash statement-as-a-page needs the dialog work from step 5. Building them before the foundations means building on top of the defects they would otherwise have exposed.
